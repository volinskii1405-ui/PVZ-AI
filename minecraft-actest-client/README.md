# AC Test Client — тестовый клиент для проверки античита

Клиентский мод Fabric для **Minecraft 1.21.4** с модулями **Speed**, **Fly**, **NoFall**, **NoSlow**, **Step**, **Reach** и **WH (ESP)**.
Нужен, чтобы проверять свой античит на своём тестовом сервере. Модули включаются
только на серверах из `allowedServers` (по умолчанию `localhost` / `127.0.0.1`) и в одиночной игре.

## Архитектура

```
ActestClient (ClientModInitializer)
 ├─ ActestConfig ............ config/actest.json (Gson), горячая перезагрузка раз в 1 с
 ├─ ModuleManager ........... список модулей, клавиши, тики, HUD
 │   ├─ ServerGuard ......... проверка allowedServers / singleplayer
 │   ├─ MovementUtil ........ общая математика ванильного движения, направление по WASD
 │   ├─ SpeedModule ......... onTick: правит X/Z velocity (режимы GROUND / BHOP)
 │   ├─ FlyModule ........... onTick: полёт по WASD/Space/Shift (MOTION) или медленное падение (GLIDE)
 │   ├─ NoFallModule ........ onGround=true при падении: в обычных пакетах (SPOOF) или отдельным пакетом (PACKET)
 │   ├─ NoSlowModule ........ onTick: скорость ходьбы без замедления от предметов и песка душ / мёда
 │   ├─ StepModule .......... клиентский модификатор атрибута step_height
 │   ├─ ReachModule ......... клиентские модификаторы entity/block_interaction_range
 │   ├─ AttributeBoost ...... временный модификатор атрибута, переустанавливается каждый тик
 │   ├─ WallhackModule ...... игроки / враждебные / мирные мобы: GLOW через mixin + 2D-рамки, имя, дистанция
 │   └─ MovementLog ......... строка [Move] на каждый тик для сверки с логами античита
 ├─ Projection .............. матрицы кадра из WorldRenderEvents.LAST → мир в экран
 ├─ ModuleListHud ........... HUD-список включённых модулей
 ├─ gui/ActestScreen ........ меню на правый Shift: вкладки категорий → модули → настройки
 │   └─ gui/widget/ ......... самописные виджеты: вкладки, переключатели, сегменты, ползунки, выбор цвета
 └─ mixin/
     ├─ ClientPlayerEntityMixin  sendMovementPackets(): учёт высоты падения + isOnGround() → true для NoFall/SPOOF
     ├─ MinecraftClientMixin  hasOutline() → true для целей WH (контур сквозь стены)
     └─ EntityMixin ......... getTeamColorValue() → цвет группы WH
```

События Fabric API:
- `ClientTickEvents.END_CLIENT_TICK`: клавиши, `Module.onTick`, проверка конфига.
- `WorldRenderEvents.LAST`: сохранение матриц камеры.
- `HudRenderCallback`: `Module.onRender` и HUD-список.

Новый модуль = класс-наследник `AbstractModule` + одна строка `register(...)` в `ModuleManager`.

## Сборка

Нужен **JDK 21** (`java -version`). Интернет нужен при первой сборке: Loom скачает Minecraft, маппинги и Fabric API.

```bash
cd minecraft-actest-client
./gradlew build          # Windows: gradlew.bat build
```

Готовый мод: `build/libs/actest-client-1.0.0.jar`.

Если Gradle не находит какую-то версию из `gradle.properties` (например, `fabric_version`),
подставьте актуальные для 1.21.4 значения с https://fabricmc.net/develop.

## Установка

1. Установите Fabric Loader для 1.21.4 через установщик с https://fabricmc.net/use/installer/.
2. Скачайте **Fabric API** для 1.21.4 (Modrinth/CurseForge) и положите jar в `.minecraft/mods`.
3. Положите туда же `actest-client-1.0.0.jar`.
4. Запустите профиль `fabric-loader-1.21.4`.

Можно запускать и из исходников: `./gradlew runClient`. Dev-клиент заходит под офлайн-ником,
поэтому на тестовом сервере нужен `online-mode=false` (или используйте обычный лаунчер).

## Управление и конфиг

| Клавиша | Действие |
|---|---|
| `R` | Speed вкл/выкл |
| `G` | Fly вкл/выкл |
| `N` | NoFall вкл/выкл |
| — | NoSlow: по умолчанию без клавиши, включается из меню |
| `J` | Step вкл/выкл |
| `K` | Reach вкл/выкл |
| `H` | WH вкл/выкл |
| `Правый Shift` | Меню настроек (повторное нажатие или `Esc` закрывает его) |

Клавиши переназначаются в «Настройки → Управление → AC Test Client».

### Меню настроек

Меню открывается на правый Shift. В шапке — вкладки категорий **Движение / Визуал / Прочее**,
слева — модули выбранной категории (зелёная точка: модуль включён), справа — настройки модуля.
Изменения применяются сразу, а при закрытии меню сохраняются в `actest.json`. Игра не встаёт на паузу
и фон не размывается, поэтому изменения сразу видно за меню.

- Категории: **Движение / Бой / Визуал / Прочее**.
- **Движение**
  - **Speed:** режим (`По земле` / `Bhop`), скорость от x1.00 до x5.00.
  - **Fly:** режим (`Полёт` / `Планирование`), горизонтальная скорость, скорость подъёма/спуска, скорость падения.
  - **NoFall:** режим (`Spoof` / `Packet`).
  - **NoSlow:** замедление от предметов и от песка душ / мёда — отдельными переключателями.
  - **Step:** высота шага от 0.6 до 3.0 блока.
- **Бой → Reach:** дальность атаки от 3.0 до 8.0, по желанию — дальность взаимодействия с блоками.
- **Визуал → WH:** вид (`Контур` / `Рамки` / `Оба`), группы игроки / враждебные / мирные мобы со своими
  переключателями и цветами (квадратик выбирает, чей цвет править), имена, дистанция, дальность,
  ползунок оттенка и палитра.
- **Прочее:** «Интерфейс» — список модулей на экране, лог движения, перечитать конфиг;
  «Клавиши» — текущие клавиши всех модулей.

Под каждой страницей модуля есть короткая подсказка по выбранному режиму. Строка модуля
показывает его клавишу. Внизу боковой панели — текущий сервер: зелёная точка означает, что модули
здесь разрешены, красная — что сервер не входит в `allowedServers` (переключатели модулей тогда неактивны,
остальные настройки менять можно).

Файл `.minecraft/config/actest.json` создаётся при первом запуске. Изменения подхватываются
на лету, примерно за секунду, без перезапуска игры:

```json
{
  "allowedServers": ["localhost", "127.0.0.1"],
  "allowSingleplayer": true,
  "debugLog": false,
  "speed": { "mode": "GROUND", "multiplier": 1.5 },
  "fly": { "mode": "MOTION", "speed": 0.5, "verticalSpeed": 0.4, "glideSpeed": 0.05 },
  "noFall": { "mode": "SPOOF" },
  "noSlow": { "items": true, "blocks": true },
  "step": { "height": 1.0 },
  "reach": { "entityRange": 4.0, "blocks": false, "blockRange": 6.0 },
  "wallhack": {
    "mode": "GLOW",
    "players": true,
    "hostileMobs": false,
    "passiveMobs": false,
    "showNames": true,
    "showDistance": true,
    "color": "#FF4040",
    "hostileColor": "#FF9020",
    "passiveColor": "#40FF40",
    "maxDistance": 128.0
  },
  "hud": { "enabled": true, "x": 4, "y": 4 }
}
```

| Параметр | Значения |
|---|---|
| `allowedServers` | `"host"` или `"host:port"`, сравнение без учёта регистра. На других серверах модули не включатся. |
| `debugLog` | `true` — в `logs/latest.log` на каждый тик пишется `[Move] age=… dXZ=… dY=… ground=… fall=… using=… nofall=… active=…` |
| `speed.mode` | `GROUND` — прямое изменение velocity на земле; `BHOP` — автопрыжки с ускорением и air strafe |
| `speed.multiplier` | 1.0–5.0, множитель к **ванильной** скорости (1.0 = как без мода) |
| `fly.mode` | `MOTION` — зависание и полёт по WASD, Space вверх, Shift вниз; `GLIDE` — медленное падение |
| `fly.speed` / `verticalSpeed` / `glideSpeed` | Блоков за тик: горизонталь 0.1–2.0, подъём/спуск 0.1–2.0, падение в GLIDE 0.01–0.3 |
| `noFall.mode` | `SPOOF` — `onGround=true` в обычных пакетах движения; `PACKET` — отдельный `OnGroundOnly(true)` каждый тик падения |
| `noSlow.items` / `blocks` | Убирать замедление от использования предметов / от песка душ и мёда |
| `step.height` | Высота шага, 0.6–3.0 (ванильная 0.6) |
| `reach.entityRange` | Дальность атаки, 3.0–8.0 (ванильная 3.0) |
| `reach.blocks` / `blockRange` | Менять ли дальность взаимодействия с блоками и её значение, 4.5–8.0 (ванильная 4.5) |
| `wallhack.mode` | `GLOW` — ванильный контур свечения; `BOX` — 2D-рамки поверх экрана; `BOTH` — оба варианта |
| `wallhack.players` / `hostileMobs` / `passiveMobs` | Какие группы подсвечивать. Враждебные: все мобы с маркером `Monster` (зомби, скелеты, криперы, слаймы, гасты, шалкеры, хоглины…). Мирные: остальные мобы (животные, жители, големы, рыбы, волки…). |
| `wallhack.color` / `hostileColor` / `passiveColor` | `#RRGGBB`, цвет контура и рамок для игроков, враждебных и мирных мобов |

## Что увидит античит

### Какие пакеты отправляет клиент

| Yarn (1.21.4) | Mojang | Когда | Поля |
|---|---|---|---|
| `PlayerMoveC2SPacket.PositionAndOnGround` / `.Full` | `ServerboundMovePlayerPacket.Pos` / `.PosRot` | Каждый тик, пока игрок двигается (сдвиг > 2·10⁻⁴), иначе раз в 20 тиков | `x, y, z, [yaw, pitch], onGround, horizontalCollision` |
| `PlayerInputC2SPacket` | `ServerboundPlayerInputPacket` | При изменении нажатых клавиш (1.21.2+) | `forward, backward, left, right, jump, sneak, sprint` |
| `ClientCommandC2SPacket` (`START/STOP_SPRINTING`) | `ServerboundPlayerCommandPacket` | Начало и конец спринта | — |

Speed, Fly и NoSlow **не отправляют своих пакетов** и не подделывают поля: они меняют только клиентскую
физику, а ваниль честно отправляет получившиеся координаты. Их нарушения видны как **неправдоподобные
смещения между соседними пакетами движения**. NoFall — единственный модуль, который трогает пакеты:
подменяет поле `onGround` (SPOOF) или шлёт лишний пакет (PACKET).

С `debugLog: true` клиентский лог пишет на каждый тик те же `dXZ/dY/onGround`, что пришли на сервер,
плюс дистанцию падения, использование предмета и действие NoFall (`nofall=SPOOF/PACKET/-`).
Строки можно сопоставить с логом античита.

### Ориентиры: смещение по горизонтали за тик, обычный блок, без эффектов

Ванильная физика: ускорение `a = movementSpeed · 0.98` (шагом 0.1, спринтом 0.13), трение на земле `·0.546` за тик,
установившийся шаг `≈ 2.2026·a`.

| | Шаг | Спринт |
|---|---|---|
| Ваниль | 0.2158 бл/тик (4.32 м/с) | 0.2806 бл/тик (5.61 м/с) |
| GROUND ×1.5 | 0.324 | 0.421 (8.4 м/с) |
| GROUND ×2.0 | 0.432 | 0.561 (11.2 м/с) |
| GROUND ×3.0 | 0.647 | 0.842 (16.8 м/с) |
| GROUND ×5.0 | 1.079 | 1.403 (28.1 м/с) |

Для сравнения: легитный спринт под Speed II даёт `0.13 · 1.4` → ≈ 0.393 бл/тик, то есть почти как GROUND ×1.4.
Античит обязан учитывать эффекты, атрибуты, лёд, сало, отброс от урона и т.п.

### Speed / GROUND — сигнатуры

- **Горизонтальная скорость на земле** (`onGround=true` в двух соседних пакетах) выше предсказанного максимума
  `2.2026 · a`, причём ровно в `multiplier` раз.
- **Нет разгона.** Ваниль выходит на максимальную скорость примерно за 5–6 тиков (геометрически),
  а здесь полная скорость наступает уже на 2-м тике движения.
- **Нет инерции при смене направления.** Вектор скорости сразу поворачивается за WASD,
  ванильного «доворота» с трением нет. Это хорошо ловят проверки на основе предсказания движения.
- **Вертикаль ванильная:** прыжок `Δy = 0.42`, дальше гравитация `(vy − 0.08)·0.98`.
  Проверки fly/gravity срабатывать **не должны** (ложное срабатывание тоже стоит проверить).
- `PlayerInputC2SPacket` и спринт согласованы с движением. Направление движения совпадает с нажатыми клавишами.

### Speed / BHOP — сигнатуры

- **Прыжок без нажатого прыжка.** Траектория прыжка (`onGround true→false`, `Δy = 0.42`) идёт
  при `PlayerInputC2SPacket.jump = false`, потому что автопрыжок вызывает `jump()` напрямую. Очень сильный сигнал.
- **Тик прыжка:** горизонтальный шаг ≈ `0.353·m + 0.127` при спринте (×1.0 ≈ 0.48, как в ванили;
  ×1.5 ≈ 0.66; ×2.0 ≈ 0.83).
- **Air strafe.** В воздухе ваниль может изменить горизонтальную скорость не больше чем на ≈0.0255 бл/тик
  (ускорение в воздухе), а здесь направление поворачивается целиком без потери модуля скорости.
- Ритм «приземлился — сразу прыгнул» с ровно одним пакетом `onGround=true` между прыжками.
  Сам по себе он не нарушение: зажатый пробел в ванили даёт то же самое.

### Fly — сигнатуры

- **MOTION, зависание:** много пакетов подряд с `onGround=false` и `Δy = 0`. В ванили в воздухе `Δy`
  каждый тик меняется по гравитации `(vy − 0.08)·0.98`, около нуля он бывает только один тик в верхней точке прыжка.
- **MOTION, подъём:** постоянный `Δy = +verticalSpeed` без опоры. Ванильный прыжок даёт максимум 0.42 и только с земли.
- **MOTION, горизонталь:** постоянная скорость `fly.speed` в воздухе и мгновенная смена направления.
  В ванили в воздухе трение `·0.91` и ускорение не больше ≈0.0255 бл/тик.
- **GLIDE:** долгое падение с постоянным `Δy = −glideSpeed`. В ванили скорость падения растёт до ≈3.9 бл/тик.
- **Ванильный кик:** при `allow-flight=false` в `server.properties` сервер сам кикает «Flying is not enabled
  on this server» после 80 тиков в воздухе. Чтобы проверять свой античит, а не ванильную проверку,
  поставьте `allow-flight=true`.

### NoFall — сигнатуры

Ванильный сервер копит дистанцию падения по `Δy` и считает урон (`дистанция − 3`), когда в пакете приходит
`onGround=true`, после чего обнуляет её. NoFall сам считает высоту падения по координатам между пакетами
и начинает сообщать «стою на земле» после 2 блоков падения, поэтому урон всегда 0.
В логе движения `fall` — клиентский `fallDistance`, `nofallFall` — высота, которую считает NoFall.

- **SPOOF:** пакеты с `onGround=true`, при этом `Δy < 0` продолжает расти, а под хитбоксом нет блока
  (и `y` не совпадает с верхом блока). Проверка: при `onGround=true` проверять коллизию под ногами на сервере.
- **PACKET:** два пакета движения за тик — обычный с `onGround=false` и `OnGroundOnly(true)` сразу после него.
  Проверки: противоречие `onGround` внутри одного тика, лишние пакеты движения (счётчик пакетов за тик).
- **Общее:** надёжнее всего считать дистанцию падения на сервере по координатам, не доверяя `onGround` клиента,
  и наносить урон по ней.

### NoSlow — сигнатуры

Сервер знает, что игрок использует предмет: начало — `PlayerInteractItemC2SPacket`, конец —
`PlayerActionC2SPacket(RELEASE_USE_ITEM)` или окончание анимации.

- **Предметы:** ванильный шаг при использовании предмета ≈ `2.2026 · 0.098 · 0.2` ≈ **0.043 бл/тик**,
  с NoSlow — обычные **≈0.216** (в 5 раз больше).
- **Песок душ / мёд:** ванильный установившийся шаг ≈ `1.28·a` (≈0.125 шагом, ≈0.163 спринтом), с NoSlow —
  как на обычном блоке (0.216 / 0.281). Зачарование Soul Speed меняет цифры — его нужно учитывать.
- Вертикаль и прыжки ванильные. Работает только на земле.

### Step — сигнатуры

- Подъём на блок за **один тик** при `onGround=true` в соседних пакетах: `Δy` до `step.height` (1.0, 1.5, 2.0…).
  Ваниль поднимает шагом максимум на 0.6, а на полный блок — только прыжком (`Δy` 0.42, затем 0.33…).
- `PlayerInputC2SPacket.jump = false` при таком подъёме.

### Reach — сигнатуры

- Атака приходит пакетом `PlayerInteractEntityC2SPacket` (Mojang: `ServerboundInteractPacket`) по цели,
  до хитбокса которой от глаз игрока больше 3.0 блока.
- Проверка: расстояние от глаз (`eyePos`) до ближайшей точки хитбокса цели в момент удара, с поправкой
  на пинг и движение цели. Ванильный сервер оставляет большой запас, поэтому строже проверяет только античит.
- С `reach.blocks` то же для ломания и установки блоков: `PlayerActionC2SPacket` / `PlayerInteractBlockC2SPacket`
  дальше 4.5 блока.

### Ванильные проверки сервера не помогут

Ванильный `ServerPlayNetworkHandler` выдаёт «moved too quickly» только при `Δ² − v² > 100`
(300 на элитрах) за один пакет, то есть около 10 блоков. «moved wrongly» касается коллизий.
Даже ×5 (1.4 бл/тик) ни одну из этих проверок не задевает, поэтому всё ловится только вашим античитом.
Исключение — Fly: ванильная проверка «полёта» сработает, если `allow-flight=false` (см. выше).

### WH / ESP — сетевого следа нет

- Модуль **ничего не отправляет на сервер.** GLOW подменяет клиентский `hasOutline()`,
  метаданные сущности (флаг свечения) на сервере не меняются. BOX и ники рисуются в HUD.
  По пакетам ESP обнаружить нельзя.
- Детект возможен только **поведенческий**: наведение прицела и преследование игроков, которых не видно,
  «префайр» из-за угла.
- **Предотвращение** работает лучше детекта: не отправлять клиенту позиции тех, кого он не может видеть.
  Например, ограничить `entity-tracking-range.players` в `spigot.yml` или прятать игроков
  вне прямой видимости (raytrace + `Player#hideEntity` / `showEntity` в Bukkit API).
  Если у клиента нет координат, ESP рисовать нечего.

### Побочные признаки клиента

- Бренд клиента (`minecraft:brand`) будет `fabric`, а Fabric API регистрирует свои каналы
  в `minecraft:register`. Сам мод своих каналов не регистрирует, поэтому по ним его не отличить
  от любой другой сборки Fabric.

## Ограничения

- Мод написан под 1.21.4 (Yarn). Под другие 1.21.x API местами отличается. Например,
  в 1.21.5+ `RenderTickCounter#getTickDelta` переименован, в 1.21.6+ HUD переезжает на `HudElementRegistry`,
  в 1.21.9+ изменены `KeyBinding` и события рендера мира.
- GLOW может не отображаться с шейдерпаками (Iris) или модами, которые отсекают невидимые сущности.
