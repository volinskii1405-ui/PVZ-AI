# AC Test Client — тестовый клиент для проверки античита

Клиентский мод Fabric для **Minecraft 1.21.4** с двумя модулями: **Speed** и **WH (ESP)**.
Нужен, чтобы проверять свой античит на своём тестовом сервере. Модули включаются
только на серверах из `allowedServers` (по умолчанию `localhost` / `127.0.0.1`) и в одиночной игре.

## Архитектура

```
ActestClient (ClientModInitializer)
 ├─ ActestConfig ............ config/actest.json (Gson), горячая перезагрузка раз в 1 с
 ├─ ModuleManager ........... список модулей, клавиши, тики, HUD
 │   ├─ ServerGuard ......... проверка allowedServers / singleplayer
 │   ├─ SpeedModule ......... onTick: правит X/Z velocity (режимы GROUND / BHOP)
 │   └─ WallhackModule ...... GLOW через mixin + onRender: 2D-рамки, ник, дистанция
 ├─ Projection .............. матрицы кадра из WorldRenderEvents.LAST → мир в экран
 ├─ ModuleListHud ........... HUD-список включённых модулей
 └─ mixin/
     ├─ MinecraftClientMixin  hasOutline() → true для целей WH (контур сквозь стены)
     └─ EntityMixin ......... getTeamColorValue() → цвет из конфига
```

События Fabric API:
- `ClientTickEvents.END_CLIENT_TICK`: клавиши, `Module.onTick`, проверка конфига.
- `WorldRenderEvents.LAST`: сохранение матриц камеры.
- `HudRenderCallback`: `Module.onRender` и HUD-список.

Новый модуль = класс-наследник `AbstractModule` + одна строка `register(...)` в `ModuleManager`.

## Сборка

Нужен **JDK 21** (`java -version`). Интернет нужен при первой сборке: Loom скачает Minecraft, маппинги и Fabric API.

```bash
cd minecraft-actest-client
./gradlew build          # Windows: gradlew.bat build
```

Готовый мод: `build/libs/actest-client-1.0.0.jar`.

Если Gradle не находит какую-то версию из `gradle.properties` (например, `fabric_version`),
подставьте актуальные для 1.21.4 значения с https://fabricmc.net/develop.

## Установка

1. Установите Fabric Loader для 1.21.4 через установщик с https://fabricmc.net/use/installer/.
2. Скачайте **Fabric API** для 1.21.4 (Modrinth/CurseForge) и положите jar в `.minecraft/mods`.
3. Положите туда же `actest-client-1.0.0.jar`.
4. Запустите профиль `fabric-loader-1.21.4`.

Можно запускать и из исходников: `./gradlew runClient`. Dev-клиент заходит под офлайн-ником,
поэтому на тестовом сервере нужен `online-mode=false` (или используйте обычный лаунчер).

## Управление и конфиг

| Клавиша | Действие |
|---|---|
| `R` | Speed вкл/выкл |
| `H` | WH вкл/выкл |
| `Правый Shift` | Меню настроек (повторное нажатие или `Esc` закрывает его) |

Клавиши переназначаются в «Настройки → Управление → AC Test Client».

### Меню настроек

Меню открывается на правый Shift. Изменения применяются сразу, а при закрытии меню сохраняются в `actest.json`.
Игра при этом не встаёт на паузу и фон не размывается, поэтому новый цвет подсветки сразу виден на игроках за меню.

- **Speed:** вкл/выкл, режим («По земле» / «Bhop»), ползунок скорости от x1.00 до x5.00 с шагом 0.05,
  показ списка модулей, debug-лог.
- **WH:** вкл/выкл, вид подсветки («Контур» / «Рамки» / «Контур + рамки»), ники, дистанция,
  дальность от 16 до 512 блоков, цвет линий (ползунки R/G/B и 8 готовых цветов), образец цвета рядом с заголовком.

Если сервер не входит в `allowedServers`, кнопки включения модулей неактивны, а остальные настройки менять можно.

Файл `.minecraft/config/actest.json` создаётся при первом запуске. Изменения подхватываются
на лету, примерно за секунду, без перезапуска игры:

```json
{
  "allowedServers": ["localhost", "127.0.0.1"],
  "allowSingleplayer": true,
  "speed": {
    "mode": "GROUND",
    "multiplier": 1.5,
    "debugLog": false
  },
  "wallhack": {
    "mode": "GLOW",
    "showNames": true,
    "showDistance": true,
    "color": "#FF4040",
    "maxDistance": 128.0
  },
  "hud": { "enabled": true, "x": 4, "y": 4 }
}
```

| Параметр | Значения |
|---|---|
| `allowedServers` | `"host"` или `"host:port"`, сравнение без учёта регистра. На других серверах модули не включатся. |
| `speed.mode` | `GROUND` — прямое изменение velocity на земле; `BHOP` — автопрыжки с ускорением и air strafe |
| `speed.multiplier` | 1.0–5.0, множитель к **ванильной** скорости (1.0 = как без мода) |
| `speed.debugLog` | `true` — в `logs/latest.log` пишется смещение за каждый тик (`[Speed] age=… dXZ=… dY=… onGround=…`) |
| `wallhack.mode` | `GLOW` — ванильный контур свечения; `BOX` — 2D-рамки поверх экрана; `BOTH` — оба варианта |
| `wallhack.color` | `#RRGGBB`, цвет контура и рамок |

## Что увидит античит

### Какие пакеты отправляет клиент

| Yarn (1.21.4) | Mojang | Когда | Поля |
|---|---|---|---|
| `PlayerMoveC2SPacket.PositionAndOnGround` / `.Full` | `ServerboundMovePlayerPacket.Pos` / `.PosRot` | Каждый тик, пока игрок двигается (сдвиг > 2·10⁻⁴), иначе раз в 20 тиков | `x, y, z, [yaw, pitch], onGround, horizontalCollision` |
| `PlayerInputC2SPacket` | `ServerboundPlayerInputPacket` | При изменении нажатых клавиш (1.21.2+) | `forward, backward, left, right, jump, sneak, sprint` |
| `ClientCommandC2SPacket` (`START/STOP_SPRINTING`) | `ServerboundPlayerCommandPacket` | Начало и конец спринта | — |

Мод **не отправляет своих пакетов** и не подделывает поля. Он меняет только клиентскую физику,
и ваниль честно отправляет получившиеся координаты. Поэтому нарушения видны как **неправдоподобные
смещения между соседними пакетами движения**. С `debugLog: true` клиентский лог даёт те же
`dXZ/dY/onGround`, что пришли на сервер за этот тик, и строки можно сопоставить с логом античита.

### Ориентиры: смещение по горизонтали за тик, обычный блок, без эффектов

Ванильная физика: ускорение `a = movementSpeed · 0.98` (шагом 0.1, спринтом 0.13), трение на земле `·0.546` за тик,
установившийся шаг `≈ 2.2026·a`.

| | Шаг | Спринт |
|---|---|---|
| Ваниль | 0.2158 бл/тик (4.32 м/с) | 0.2806 бл/тик (5.61 м/с) |
| GROUND ×1.5 | 0.324 | 0.421 (8.4 м/с) |
| GROUND ×2.0 | 0.432 | 0.561 (11.2 м/с) |
| GROUND ×3.0 | 0.647 | 0.842 (16.8 м/с) |
| GROUND ×5.0 | 1.079 | 1.403 (28.1 м/с) |

Для сравнения: легитный спринт под Speed II даёт `0.13 · 1.4` → ≈ 0.393 бл/тик, то есть почти как GROUND ×1.4.
Античит обязан учитывать эффекты, атрибуты, лёд, сало, отброс от урона и т.п.

### Speed / GROUND — сигнатуры

- **Горизонтальная скорость на земле** (`onGround=true` в двух соседних пакетах) выше предсказанного максимума
  `2.2026 · a`, причём ровно в `multiplier` раз.
- **Нет разгона.** Ваниль выходит на максимальную скорость примерно за 5–6 тиков (геометрически),
  а здесь полная скорость наступает уже на 2-м тике движения.
- **Нет инерции при смене направления.** Вектор скорости сразу поворачивается за WASD,
  ванильного «доворота» с трением нет. Это хорошо ловят проверки на основе предсказания движения.
- **Вертикаль ванильная:** прыжок `Δy = 0.42`, дальше гравитация `(vy − 0.08)·0.98`.
  Проверки fly/gravity срабатывать **не должны** (ложное срабатывание тоже стоит проверить).
- `PlayerInputC2SPacket` и спринт согласованы с движением. Направление движения совпадает с нажатыми клавишами.

### Speed / BHOP — сигнатуры

- **Прыжок без нажатого прыжка.** Траектория прыжка (`onGround true→false`, `Δy = 0.42`) идёт
  при `PlayerInputC2SPacket.jump = false`, потому что автопрыжок вызывает `jump()` напрямую. Очень сильный сигнал.
- **Тик прыжка:** горизонтальный шаг ≈ `0.353·m + 0.127` при спринте (×1.0 ≈ 0.48, как в ванили;
  ×1.5 ≈ 0.66; ×2.0 ≈ 0.83).
- **Air strafe.** В воздухе ваниль может изменить горизонтальную скорость не больше чем на ≈0.0255 бл/тик
  (ускорение в воздухе), а здесь направление поворачивается целиком без потери модуля скорости.
- Ритм «приземлился — сразу прыгнул» с ровно одним пакетом `onGround=true` между прыжками.
  Сам по себе он не нарушение: зажатый пробел в ванили даёт то же самое.

### Ванильные проверки сервера не помогут

Ванильный `ServerPlayNetworkHandler` выдаёт «moved too quickly» только при `Δ² − v² > 100`
(300 на элитрах) за один пакет, то есть около 10 блоков. «moved wrongly» касается коллизий.
Даже ×5 (1.4 бл/тик) ни одну из этих проверок не задевает, поэтому всё ловится только вашим античитом.

### WH / ESP — сетевого следа нет

- Модуль **ничего не отправляет на сервер.** GLOW подменяет клиентский `hasOutline()`,
  метаданные сущности (флаг свечения) на сервере не меняются. BOX и ники рисуются в HUD.
  По пакетам ESP обнаружить нельзя.
- Детект возможен только **поведенческий**: наведение прицела и преследование игроков, которых не видно,
  «префайр» из-за угла.
- **Предотвращение** работает лучше детекта: не отправлять клиенту позиции тех, кого он не может видеть.
  Например, ограничить `entity-tracking-range.players` в `spigot.yml` или прятать игроков
  вне прямой видимости (raytrace + `Player#hideEntity` / `showEntity` в Bukkit API).
  Если у клиента нет координат, ESP рисовать нечего.

### Побочные признаки клиента

- Бренд клиента (`minecraft:brand`) будет `fabric`, а Fabric API регистрирует свои каналы
  в `minecraft:register`. Сам мод своих каналов не регистрирует, поэтому по ним его не отличить
  от любой другой сборки Fabric.

## Ограничения

- Мод написан под 1.21.4 (Yarn). Под другие 1.21.x API местами отличается. Например,
  в 1.21.5+ `RenderTickCounter#getTickDelta` переименован, в 1.21.6+ HUD переезжает на `HudElementRegistry`,
  в 1.21.9+ изменены `KeyBinding` и события рендера мира.
- GLOW может не отображаться с шейдерпаками (Iris) или модами, которые отсекают невидимые сущности.
  В таком случае используйте `BOX`.
- Расчёт скорости откалиброван под обычный блок (скользкость 0.6). На льду и сале цифры будут другими.
